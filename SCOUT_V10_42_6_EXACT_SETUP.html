Scout v10.42.6

Sending Stability Setup

This release removes browser/cron schedule collisions, replaces one-second page polling with a controlled worker check, prevents follow-up preview timeouts from appearing as send failures, and preserves the corrected Settings version check.

1. Supabase

1
Open the existing Scout project. Go to SQL Editor → New query.
2
Run the complete file:
RUN_THIS_V10_42_6_SENDING_STABILITY_IN_CURRENT_SUPABASE.sql
3
The final row must show scout_v10426_status = READY. All index/function/version fields must be true. worker_ready should be true when the existing Vault setup is present.
4
Run:
VERIFY_SCOUT_V10_42_6.sql
Every passed value should be true.

2. Deploy code

Place the ZIP directly in Windows Downloads. Open Git Bash manually and paste:

cd ~/Downloads

ZIP="$(find "$HOME/Downloads" -maxdepth 1 -type f -iname 'SCOUT_FULL_VERIFICATION_V10_42_6_SENDING_STABILITY_FIX*.zip' -printf '%T@ %p\n' 2>/dev/null | sort -nr | head -n 1 | cut -d' ' -f2-)"

if [ -z "$ZIP" ] || [ ! -f "$ZIP" ]; then
  echo "ERROR: Scout v10.42.6 ZIP was not found in Downloads."
else
  SOURCE="$HOME/Downloads/SCOUT_FULL_VERIFICATION_V10_42_6_SENDING_STABILITY_FIX"
  rm -rf "$SOURCE"
  unzip -q -o "$ZIP" -d "$HOME/Downloads"
  chmod +x "$SOURCE/RUN_DEPLOY_AND_KEEP_GIT_BASH_OPEN.sh"
  bash "$SOURCE/RUN_DEPLOY_AND_KEEP_GIT_BASH_OPEN.sh"
fi
The log must contain GITHUB PUSH VERIFIED. The script creates a backup branch before changing main.
The script runs npm ci → release checks → SQL checks → TypeScript typecheck → production build before it can push. If any gate fails, GitHub main is not changed.

  • Version: 10.42.6

Then open Settings → Run fast check → Run deep worker test. The central worker should be ready.

4. Sending acceptance

  • Start a controlled job of 5 emails.
  • The page should say the job is queued; it should not wait for the worker response.
  • Live Work should begin within about 30 seconds.
  • The Send Emails page must not create repeated “Due send processed” entries every second.
  • A healthy worker stays configured; page refreshes do not recreate the cron job.
  • No red 57014 should appear because a follow-up preview timed out.
  • A preview timeout should display only a local “Queue refresh delayed” notice.
  • Closing Scout must not stop the central worker.
Do not click Send Now repeatedly. One click creates one durable schedule; the central worker owns continuation.
