Corrected behavior
- Start Job no longer waits up to 55 seconds for the worker.
- Continue Job no longer treats a worker timeout as a failed resume.
- Run Due Sends Now wakes/confirms the central worker instead of launching a second worker execution.
- AppOpenRunner wakes the worker at a low frequency and never executes schedule chunks itself.
- Central worker cadence is 30 seconds with a 55-second HTTP allowance.
- The Send Emails page no longer wakes the scheduler every second; page-level confirmation is limited to every 30 seconds.
- Worker setup is status-first, so a healthy cron job is not repeatedly unscheduled and recreated.
- Follow-up preview and exact count run sequentially to avoid doubling the same history scan.
- Follow-up preview loads 250 rows by default and expands to 1,000 only when exact prospects are opened.
- Preview/count timeouts stay inside the Follow-ups card and do not appear as a red sending failure.
- Cached due totals remain usable; Send all is disabled when the exact count is not confirmed.
- Follow-up count SQL no longer calls the full 50,000-row preview function.
- Partial indexes support sent-message rollup, reply classification, due schedules and stale recovery.
- Schema version is checked by the required version row, preventing tied timestamps from returning an older version.
