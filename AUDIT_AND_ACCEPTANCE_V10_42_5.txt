SCOUT V10.42.5 — READINESS AND PAGE STABILITY AUDIT
====================================================

Problems corrected
------------------
1. PostgreSQL 57014 timeouts are classified as Degraded, not as missing schema.
2. The fast Settings check uses a metadata-only database probe and does not execute message-worker or follow-up queue scans.
3. The deep worker ping is separate and bounded.
4. Structured health responses are rendered safely instead of [object Object].
5. A failed contactable-lead count preserves the last confirmed count and never substitutes zero.
6. Gmail connection, sender verification, limit controls, signatures and app setup are blocked only when a required database object is confirmed missing.
7. Settings shows both the app-required schema version and the installed database version.
8. Temporary workspace/auth/Supabase reads receive bounded safe retries.
9. A segment-level Scout error boundary keeps the existing Scout shell/menu available and automatically retries transient page loads.
10. The root recovery screen states that saved data is retained and avoids replaying completed mutations.
11. v10.42.4 indexed Ready Email Detection remains included in the combined SQL and release.
12. Owner-selected sender limits are preserved; recommended 250 daily / 100 per run values are prepared only after an explicit click and are not saved silently.

Dependency-backed build limitation
----------------------------------
A complete npm ci, tsc --noEmit and Next.js production build could not be completed inside this isolated artifact environment because the internal npm package registry returned HTTP 503 for required packages. This is not recorded as a successful build.

The included deployment script enforces, in order, before GitHub is changed:
- npm ci
- npm run verify:static
- npm run verify:sql-contract
- npm run typecheck
- npm run build

The script prints GITHUB PUSH VERIFIED only after the validated commit is confirmed on GitHub main.
